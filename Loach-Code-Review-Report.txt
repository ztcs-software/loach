Detailed Findings

F-001 [High] TypeScript build currently fails
Area: Build / frontend
Evidence: package.json:10; src/lib/files.ts:87; src/stores/settingsStore.ts:25,42,44
Impact: The production build script runs tsc --noEmit before vite build, and tsc currently exits with errors. A clean frontend build is blocked.
Recommendation: Add or declare the mammoth/mammoth.browser type, remove the unused Zustand get parameter, and narrow settings casts through unknown or a typed serializable settings shape.

F-002 [High] Per-chat model, system prompt, and parameter changes are not persisted
Area: Chat state / database contract
Evidence: src/stores/chatStore.ts:735,762,770; src/components/ChatHeader.tsx:251; src/components/ParameterPanel.tsx:101,379; src-tauri/src/db.rs:355
Impact: The UI applies per-chat overrides in memory, but the setters do not call a backend persistence command. Restarting or rehydrating loses provider/model/system prompt/parameter changes even though Database::update_session_meta exists.
Recommendation: Expose a Tauri command around update_session_meta and have the three frontend setters persist changes with rollback or a user-visible failure state.

F-003 [High] Renderer-callable commands include arbitrary file write and destructive database actions
Area: Tauri command security
Evidence: src-tauri/src/commands.rs:271,808,837,867,875; src/lib/tauri.ts:621,631; src-tauri/tauri.conf.json:13; src-tauri/capabilities/default.json:23
Impact: A compromised renderer can invoke privileged commands directly. write_text_file trusts a caller-supplied path, import_data_json reads a caller-supplied path and replaces state, and wipe/reset/security-clear commands do not require a fresh credential at the command boundary.
Recommendation: Move file selection and write/read work into backend-owned commands, require fresh unlock/credential checks for destructive commands, reduce plugin capabilities, and disable withGlobalTauri unless it is required.

F-004 [High] Database restore and wipe paths can leave SQLite foreign-key checks disabled
Area: Database integrity
Evidence: src-tauri/src/db.rs:1037,1187,1210,1223,1232,1246
Impact: restore_snapshot, wipe_user_data, and wipe_all disable PRAGMA foreign_keys and re-enable it only on the success path. Any early error leaves enforcement disabled on the shared connection. Restore also allows orphaned references without a final foreign_key_check.
Recommendation: Use a guard/finally-style pattern that always restores PRAGMA foreign_keys = ON, validate the imported graph before commit or run PRAGMA foreign_key_check, and fail restore if referential integrity is broken.

F-005 [High] npm audit reports one high and three moderate vulnerabilities
Area: Dependencies
Evidence: package-lock.json; npm audit JSON output; src/lib/files.ts:86
Impact: The high advisory is in @xmldom/xmldom 0.8.12 via Mammoth, which is relevant because the app parses user-supplied DOCX files. Moderate advisories affect postcss, vite, and esbuild.
Recommendation: Upgrade or override the XML parser to a fixed version, update postcss to at least 8.5.10, and plan a Vite/esbuild dev-toolchain upgrade with regression testing.

F-006 [Medium] Application lock has no backend rate limiting and can be cleared without credential re-entry
Area: Security lock
Evidence: src-tauri/src/security.rs:179,206; src-tauri/src/commands.rs:271; src/stores/securityStore.ts:78; src/components/SecurityPanel.tsx:46
Impact: Unlock verification has no attempt counter, delay, lockout, or audit trail. security_clear removes the stored lock without requiring the current PIN/password, relying only on UI flow.
Recommendation: Enforce rate limiting in Rust, require current credential confirmation for clearing or changing the lock, and treat the frontend lock as UX while the backend enforces policy.
F-007 [Medium] Unicode handling can corrupt fetched text or panic while truncating
Area: Web fetch / MCP helpers
Evidence: src-tauri/src/tools/fetch_url.rs:368,389,489; src-tauri/src/mcp/client.rs:195
Impact: HTML stripping/entity decoding treats UTF-8 bytes as chars, producing mojibake for non-ASCII pages. Two truncation helpers slice strings by byte offsets that may not be UTF-8 character boundaries.
Recommendation: Iterate over chars or use an HTML/text parser for extraction. Make truncation character-boundary-safe with char_indices and add tests for accented, CJK, emoji, and long non-ASCII input.

F-008 [Medium] Streaming parsers can grow memory without bound on malformed streams
Area: Provider streaming
Evidence: src-tauri/src/providers/openai.rs:203,205,290; src-tauri/src/providers/ollama.rs:174,477
Impact: OpenAI SSE parsing waits for a blank-line delimiter only, ignores CRLF framing, and has no buffer cap. Ollama admin/chat JSONL parsing similarly accumulates until newline. A broken or hostile configured endpoint can cause memory growth or dropped final data.
Recommendation: Cap stream buffers, support CRLF framing, flush/validate final buffered data on EOF, and abort streams that exceed sane frame limits.

F-009 [Medium] Model admin stream promise can hang if a stream finishes before polling starts
Area: Models store
Evidence: src/stores/modelsStore.ts:344,356,384,389
Impact: runAdminStream starts the backend stream before registering the active handle and polling subscription. A fast done/error event can set finished before the subscription exists, leaving pull/create operations unresolved and leaking the handle until manual cleanup.
Recommendation: Register the run before starting the stream or check the current finished flag immediately after subscribing. Prefer event-driven promise resolution over polling store state.

F-010 [Medium] Modelfile generation permits directive injection and malformed quoted blocks
Area: Model administration
Evidence: src/lib/modelfile.ts:32,35,38; src/components/ModelsView.tsx:132,267
Impact: The FROM value is interpolated without model-tag validation, so newline characters can inject extra directives. SYSTEM and TEMPLATE triple-quote blocks do not escape embedded triple quotes, allowing malformed or attacker-controlled Modelfiles.
Recommendation: Validate model names/tags with a conservative allowlist, reject control characters, and escape or encode triple-quoted content according to Ollama Modelfile rules.

F-011 [Medium] MCP server headers are stored as plaintext JSON and input validation is minimal
Area: MCP configuration
Evidence: src-tauri/src/commands.rs:688,710; src-tauri/src/db.rs:88,204; src/components/McpPanel.tsx:342
Impact: The UI supports auth headers, but those secrets are serialized into SQLite and can be included in exports/restores. URL validation only checks non-empty fields and does not enforce scheme, header names, header size, or internal-network policy.
Recommendation: Store secret header values in the OS keyring or a redacted secret table, redact exports by default, validate URL scheme/host/header syntax, and warn or block internal endpoints where appropriate.

F-012 [Medium] Attachment extraction and message persistence are effectively unbounded after the 15 MB file cap
Area: Files / chat persistence
Evidence: src/lib/files.ts:63,86,164; src/stores/chatStore.ts:838
Impact: PDF/DOCX extraction returns full text, inlineTextAttachments appends it all to prompts, and serialized attachments include rich content. Large documents can bloat SQLite, freeze the UI, and overflow provider context windows.
Recommendation: Add extracted-text character/token caps, page limits, progressive extraction, attachment summarization, and separate blob storage or pruning for large persisted payloads.

F-013 [Medium] Failed stream startup leaves empty assistant messages behind
Area: Chat error handling
Evidence: src/stores/chatStore.ts:360,396,457
Impact: startTask creates and persists an assistant placeholder before startChatStream. If starting the stream throws, the catch block clears running state but does not remove or mark the placeholder, leaving blank assistant messages in the transcript.
Recommendation: On startup failure, delete the placeholder or convert it into a visible error message, and keep database/session state consistent with the UI.

F-014 [Medium] Settings writes are optimistic without rollback on persistence failure
Area: Settings store
Evidence: src/stores/settingsStore.ts:56,72
Impact: The store updates local state before backend persistence. If setSetting fails, UI state and the SQLite settings table can diverge, especially in two-step provider-default changes.
Recommendation: Persist first or roll back on error, surface failures to the user, and batch related settings updates in a single backend command or transaction.

F-015 [Medium] CSP and Tauri capability posture is inconsistent and broader than necessary
Area: Desktop hardening
Evidence: index.html:6; src-tauri/tauri.conf.json:13,33; src-tauri/capabilities/default.json:23,24
Impact: The HTML CSP and Tauri CSP differ, making behavior harder to reason about. Tauri permits global API exposure, broad HTTPS connect-src, fs default permissions, and shell open permission, expanding renderer-bug blast radius.
Recommendation: Unify CSP in one source of truth, narrow connect-src to required endpoints where practical, remove global Tauri exposure, and replace broad plugin permissions with least-privilege capability entries.
